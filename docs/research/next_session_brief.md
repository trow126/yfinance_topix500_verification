### 3.2 データで分かったこと（落とし穴）

- yfinance は上場廃止銘柄を返さない。JPX の廃止一覧（2017〜2026、`data/rankings/jpx_delisted_2017_2026.tsv`）は取得済みだが株価は無い。J-Quants 無料版にある 2024-05 以降の廃止 23 銘柄（売買代金 10 億円以上）を補っても配当利回り系の結果は不変だった
- yfinance の 1306 は 2015-01-05 の 1:10 分割が未記録、2026-03-30・31 の終値が 1/10。`src/data/benchmark.py` と `fix_transient_scale_errors` で補正済み。個別株の ±45% 超の分割未記録は `excluded_codes` で除外（付録 E）
- yfinance は休場日の行（出来高 0）を返す。`MarketPanel` で除外済み
- J-Quants 無料版は 2024-05-13〜2026-05-11 の 2 年分のみ（日足・財務・銘柄マスタ）。配当の照合には使えた（yfinance の配当に過大記録なし）
- EDINET API の大量保有報告書は 2021-11 から一覧に出る。CSV（type=5）に保有目的・発行者コード・保有割合がある。取得スクリプトは `scripts/data/fetch_edinet_large_holdings.py`（再開可能、0.3 秒間隔で約 1 時間）
- EDINET のコードリスト（E コード → 証券コード）は `https://disclosure2dl.edinet-fsa.go.jp/searchdocument/codelist/Edinetcode.zip`
- 金融庁の HFT 統計（`HFT_ja.zip`）: 売買代金の 34〜39% が HFT、注文件数の 8 割超。引け別の内訳は無い

### 3.3 方法で分かったこと

- 口座全体の日次シャープレシオの DSR は市場の動きに支配され、「1306 を上回る力」を測れない。対 1306 の超過リターンで判定すべき（4 章で改訂）
- 「毎月ランダム」の比較は売買コストで不利すぎて甘い。売買回数をそろえた固定乱数（`pick="random_sticky"`）やイベントと同じ日・同じ候補からのランダムを使う
- 1306 側の「期末一括課税」は短い期間ほど 1306 に不利に働く。それでも 2026 年は戦略が負けた
- 3 期間を同時に出すと探索期間と確認期間の区別がなくなる。第 2 期は 2023-25 以降を封印する
- 1 件の極端な成功例（H8 の 8105）が平均を作る。中央値・勝率・上位 N 件除外後の損益を必ず出す

## 4. 合格基準（第 1 期の 4 章を次のとおり改訂する）

比較対象は変わらず「1306 を期間の最初に全額買って持ち続けた場合」（分配金は税引後現金、期末一括課税）。これに加えて「売らずに持ち続ける（税を先送り）」版も出す。

1. **税引後・コスト込みで 1306 を上回る**（第 1 期と同じ税・スリッページ。手数料は 0 円と明記）。**約定はシグナル確定日の翌営業日の終値**に変える（第 1 期は当日終値）
2. **現金を遊ばせない**（待機資金は 1306）
3. **探索期間と確認期間を分ける**: 探索は 2015-18 と 2019-22、確認は 2023-25 と 2026 年（取得済み: `data/cache/universe_2026`、2026-10-08 まで）。確認期間は事前登録した条件を 1 回だけ回し、結果を見て条件を変えない
4. **偶然でない**: (a) 同じ候補・同じ頻度・同じ売買回数のランダム選定 20 回以上の上位 10%、(b) **対 1306 の日次超過リターンの PSR ≥ 0.95**、(c) **ブロックブートストラップ（ブロック 20 営業日、10,000 回）で累積超過が正になる確率 ≥ 0.95**、(d) 試した条件の数で割り引いた DSR（超過リターン版）も併記。いずれも探索期間・確認期間の両方で
5. **リスク**: 最大 DD の悪化が 1306 比 10 pt 以内。**上位 3 件の取引を除いても 1306 を上回る**（極端値依存の排除）
6. **運用できる**: 手動・月数回、1 銘柄の売買代金 ≤ その銘柄の 1 日売買代金の 1%
7. **コスト感度**: 片道 0 / 0.05 / 0.10 / 0.20 / 0.30% で符号が反転する水準を表にし、0.20% でも上回ること

すべての判定は `scripts/run/` の既存スクリプトと `src/backtest/stats.py`（`probabilistic_sharpe_ratio`、`block_bootstrap_outperform`、`deflated_sharpe_ratio`、`random_rank`）で出せる。

## 6. 進め方

1. **仮説を先に書く**: `docs/research/hypotheses.md` に 3d 章以降として追記する（仮説・理由・データ・合格基準・条件の最大数・予想の確率）。**コミットしてから**データ取得とバックテスト。結果を見て条件を足す場合は 7 章に理由と日付
2. **データの確認を先に書く**: 期間・銘柄数・欠損・生存者バイアスの向き・ルックアヘッドの有無。新しいデータ源は 1 銘柄を手で突き合わせる（第 1 期の 1306 分割のような不備を探す）
3. **実装**: `src/backtest/rules_engine.py` に戦略クラスを足す（`Strategy` プロトコル: 毎営業日 `orders()` を返す）。既存の `FactorStrategy` / `PostExRebound` / `YearEndLosers` / `EventHold` / `IndexTiming` を参考に。テストは合成データで（`tests/test_rules_strategies.py`）
4. **検証**: 探索期間で条件を選び、確認期間は 1 回だけ。コスト感度表を必ず出す。ランダム比較は売買回数をそろえる
5. **報告**: `docs/research/report_<日付>.md` に 8 章の形式。数値は結果 TSV と照合し、独立したレビュー（数値照合・論理）を 1 回通してからコミット

## 7. 禁止事項・注意

- 結果を見てから条件を足し続けない。足した条件はすべて記録し、DSR の N に入れる
- 確認期間（2023-25、2026 年）を見て条件を変えない。見た時点でその期間は探索用に降格
- 未来の情報を使わない（発表日基準、修正前の値、当時の構成銘柄）。財務データは決算期末ではなく発表日で付ける
- 上場廃止銘柄が欠けていることの影響の向きを仮説ごとに書く
- `.env` のキーの値を表示・ログ出力・コミットしない。例外メッセージに URL が入ることがあるので、通信エラーは例外の種類だけを出す
- 実際の発注や証券口座の操作はしない。個別銘柄の推奨はしない
- EDINET・JPX・yfinance への連続アクセスは間隔を空ける（EDINET は 0.3 秒以上）
- 新しい数値を報告に書くときは、根拠ファイル（TSV・ログ）を `data/results/` に残す

## 8. 報告の形式

`docs/research/report_<日付>.md` に:

1. 結論（1〜3 行）: 合格基準を満たす戦略が見つかったか
2. 試した仮説の一覧と、基準 1〜7 ごとの合否（探索期間・確認期間を分けて）
3. 合格した戦略があれば: 運用ルール、期間ごとの結果表（1306 比・税引後、売らない版との比較）、ランダム比較の分布、コスト感度表、上位 3 件除外後の損益、最大 DD、必要資金、想定される弱点
4. データの制約（生存者バイアス、欠損、期間、ルックアヘッド）と、結論に与える影響の向き
5. 事前登録した予想との照合（当たり・外れ）
6. 次に調べる価値があるもの
7. 付録: 再現手順（コミットとコマンド）、事後の点検、除外銘柄

数値は「税引前／税引後」「優待・配当の見積もりを含むか」「約定は当日終値か翌営業日終値か」を必ず明記する。
